# اسکوپ‌ها (`user_keys`)

سرور MCP اُتی‌پی‌آی‌آر ابزارهای حساس نوشتن و صورتحساب را پشت یک **کلید کاربری** (`otpy_uk_...`) قرار می‌دهد — اعتباری جدا از کلید API پروژه. هر چک در هر فراخوانی به‌صورت زنده با API تأیید می‌شود.

## مدل اسکوپ

هر کلید کاربری دقیقاً دو اسکوپ مستقل دارد، به‌علاوه یک فلگ مشتق:

| اسکوپ | دسترسی |
|---|---|
| `write` | `send_test_otp`، `verify_test_otp`، `create_api_key` |
| `billing` | `get_balance`، `list_api_keys` |
| `root` (مشتق: `write AND billing`) | همه موارد بالا — فقط مخفف، هرگز گرنت جداگانه نیست |

هیچ مجوز سوم جداگانه‌ای وجود ندارد. `root` همیشه محاسبه می‌شود و هرگز ذخیره یا مستقیم تنظیم نمی‌شود.

## تأیید چگونه کار می‌کند

هر فراخوانی ابزار محافظت‌شده با `write` یا `billing` یک **درخواست شبکه واقعی** به `GET /v1/user-keys/self` می‌زند و `OTPY_USER_KEY` شما را به‌عنوان Bearer ارائه می‌دهد. API آن را هش کرده و ردیف زنده جدول `user_keys` را بررسی می‌کند.

- کلید را لغو کنید یا اسکوپ‌هایش را در داشبورد کم کنید → همان فراخوانی بعدی بلافاصله منعکس می‌شود.
- **هیچ کش محلی** از اسکوپ‌ها وجود ندارد.
- **هیچ دورزدن سمت کلاینتی** وجود ندارد. فلگ قدیمی `OTPY_MCP_WRITE` / `--write` کاملاً حذف شده — هرگز سمت سرور تأیید نمی‌شد و به هر کسی با دسترسی شل اجازه دورزدن می‌داد. الان بی‌اثر است.

اگر `OTPY_USER_KEY` تنظیم نشده باشد، همه ابزارهای محافظت‌شده با `write`/`billing` رد می‌شوند؛ فقط ابزارهای خواندنی بدون اسکوپ (`get_usage`، `get_integration_snippet`) با همان کلید API پروژه کار می‌کنند.

## گرنت‌های پروژه

یک کلید کاربری می‌تواند به پروژه‌های مشخص محدود شود (`user_project_grants`، مدیریت در تب **Integrate**):

- **صفر ردیف گرنت** → نامحدود: کلید روی هر پروژه‌ای که مالکش به آن دسترسی دارد کار می‌کند.
- **یک یا چند ردیف گرنت** → محدود به دقیقاً همان شناسه‌های پروژه.

هر فراخوانی ابزاری که `project_id` دارد، گرنت را همراه با چک اسکوپ بررسی می‌کند (همان درخواست زنده) و اگر کلید به آن پروژه گرنت نشده باشد، فراخوانی رد می‌شود.

## اعمال نقش (SQL)

فراتر از اسکوپ‌ها، توابع SQL زیرساخت نقش عضویت پروژه را هم اعمال می‌کنند:

- `create_api_key` → مالک باید `admin` یا `dev` پروژه باشد.
- `list_api_keys` / `get_balance` → مالک باید `admin`، `dev` یا `finance` باشد (موجودی به `member` هم اجازه می‌دهد).

همه احراز مجوز در توابع `SECURITY DEFINER` پستگرس است — هرگز در کد اپلیکیشن نیست.

## گرفتن کلید کاربری

1. تب **Integrate** در [dash.otpy.ir](https://dash.otpy.ir) را باز کنید.
2. یک کلید کاربری با اسکوپ‌های موردنیاز بسازید (`write`، `billing`، یا هر دو).
3. سکرت خام `otpy_uk_...` را بلافاصله کپی کنید — فقط یک بار نمایش داده می‌شود.
4. آن را به‌عنوان `OTPY_USER_KEY` (یا `--user-key`) در کانفیگ کلاینت MCP تنظیم کنید.
